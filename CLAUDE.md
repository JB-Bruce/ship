# Bateau — jeu web 3D de combat naval

Three.js + TypeScript + Vite. Ambiance pirates XVIIe-XVIIIe (fantasy possible), style low-poly, sensation façon AC IV Black Flag.
Règles de gameplay et décisions : `docs/GAME_DESIGN.md` (à lire avant d'ajouter une mécanique).

## Commandes
- `npm run dev` : serveur sur le port 5173 (config de preview `.claude/launch.json` : « jeu »). L'utilisateur le lance souvent lui-même via `Lancer le jeu.bat` : si le port est pris, ouvrir simplement `http://localhost:5173`.
- `?debug` dans l'URL = panneau lil-gui + FPS, et `window.game` exposé. Si le panneau navigateur est masqué, le rAF est gelé : pour tester, `game.renderer.setAnimationLoop(null)` puis appeler `game.frame(t)` avec un `t` croissant (ms), puis recharger la page. Pour mesurer les performances, utiliser les requêtes de temps GPU (`EXT_disjoint_timer_query_webgl2`) en comparant A/B dans la même session : les temps « réels » sont faussés quand le panneau est masqué, et la puce graphique change de vitesse. Les résultats des requêtes n'arrivent qu'entre deux images (laisser la main au navigateur).
- `npm run typecheck` : vérification TypeScript (à lancer après chaque modification).
- `npm run build` : typecheck + build de production.
- TypeScript reste en v6 : la v7 ne fournit plus `tsserver.js`, dont dépend le plugin typescript-lsp.

## Règles d'architecture
- **Un seul code de bateau** (`src/ship/ship.ts`) pour joueur, alliés et ennemis. Un contrôleur (clavier ou IA) remplit `ShipControls` et le bateau l'exécute. Une IA ne modifie jamais directement la position d'un bateau.
- **Types de bateaux** (`src/shipTypes.ts`, caractéristiques de base dans `src/shipStats.ts`) : stats joueur et ennemi, prix, tables d'amélioration et de masse par type. Un nouveau type = une entrée ici, plus un modèle qui implémente `ShipModel` (`ship/shipModel.ts`). Une amélioration dont la table est vide n'existe pas pour ce type (elle est cachée dans le menu). **Allongements** (`ShipTypeDef.extensions`, liste ordonnée ; le brigantin et la corvette en ont un, la frégate deux) : niveau `UpgradeLevels.extension` = nombre faits (hors `UPGRADE_IDS`), achetés au chantier (`Harbor.extendShip`) ; leurs effets se cumulent dans `deriveStats` (longueur, vie, vitesse, virage) et la masse (`appliedExtensions`) ; les derniers niveaux de certaines tables (`extraLevels` de chaque allongement, dans l'ordre) ne s'ouvrent qu'avec eux (`maxLevel(type, id, levels)`, `nextCost(type, id, levels)`, `extensionLevels`) ; le modèle se reconstruit sur place via `ShipModel.setExtension(niveau)` (appelé par `Ship.applyLooks`, puis `ShipDressing.refresh`). Nom et icône : `typeName(type, niveau)`, `shipIcon(type, levels)` / `extensionIcon(type, index)`. Un modèle allongeable a un plan paramétré (`frigateLayout(niveau)`, `corvetteLayout(niveau)`, `brigantineLayout(niveau)`) bâti avec `parts/hullStretch.ts` (`hullStretch` : parties en u de base qui s'étirent, le reste glisse ; `purchaseOrder` : ordre d'achat de sabords réguliers), des gabarits en cache par plan et par livrée, et se reconstruit dans un groupe `body` (les drapeaux de `ShipDressing` restent sur `root`).
- **Modèles 3D** générés en code : `ship/rowboat/`, `ship/longboat/`, `ship/sloop/`, `ship/brigantine/` (plan dans `brigantineLayout.ts` : le pont principal s'étire ; `gunSlots` dans l'ordre d'achat, dont un canon sous le gaillard d'avant une fois allongé ; voiles qui ne s'élargissent presque plus au-delà du niveau 3), `ship/corvette/` (plan dans `corvetteLayout.ts` : la partie droite du milieu s'étire ; `corvetteArmament` : batterie, puis pont, puis sabords de la corvette allongée), `ship/frigate/` (plan dans `frigateLayout.ts` : `frigateLayout(niveau)` donne le plan selon les allongements : les parties `SECTIONS` (arrière du gaillard d'arrière, partie droite du milieu, avant du gaillard d'avant) s'étirent selon `EXTENSION_SPLIT`, le reste glisse ; sabords de batterie réguliers (`BATTERY_SPAN`, 2 de plus par allongement), canons de gaillard `DECK_SLOTS` par niveau ; les positions s'écrivent en « u de base » de la frégate de 28 m, converties par `L.base` / `L.at` / `L.widthAt`, ou en u de la coque avec `L.station` / `L.width` ; décor de poupe dans `frigateDecor.ts` ; `frigateArmament` répartit les canons entre batterie et gaillards ; gabarits en cache par plan et par livrée), avec des pièces communes dans `ship/parts/` (`HullShape` = coque à partir d'un gabarit de sections, éventuellement en paliers, avec rentrée des flancs `tumblehome` en option : largeur réelle à une hauteur via `halfWidthAt`, lisses à hauteur variable `buildRailAt`, bandes peintes `buildBand` ; `sails.ts` = voiles génériques, carrées, focs et auriques ; `deckFittings.ts` = escaliers et écoutilles). Les pièces fixes sont fusionnées par matériau (`utils/geometryBatch.ts`) et mises en cache par livrée. Seules les pièces animées sont propres à chaque instance.
- **Équipage animé** (`deckCrew/`, réglages `DECK_CREW`) : les navires pontés (sloop, brigantin, corvette, frégate) n'ont plus de marins figés dans leur géométrie ; chaque modèle déclare un `ShipModel.deckPlan` (`ship/deckPlan.ts` : nombre de matelots, barre, vigie, promenades, postes aux cordages, `isOpenGun` = canons servis à découvert), tiré du plan du navire (il suit l'allongement). `DeckCrew` (dans `Game`) crée un `ShipCrew` pour chaque navire proche de la caméra et hors de la brume (`drawDistance`) et l'oublie quand le navire quitte le monde ; tous les marins du monde sont dessinés en 7 lots `InstancedMesh` (`sailorMeshes.ts`, une partie du corps par lot, chemise en couleur d'instance), posés chaque image par `sailorPose.ts`. Comportements dans `shipCrew.ts` (tâches : canons, à couvert, cordages, réparation, chute à l'eau, retour), mouvements et gestes dans `sailorMotion.ts`. Un tir se lit sur `Ship.cannonCooldowns` (un nouveau tableau = canons refaits, pas un tir) ; un coup reçu, sur la vie. Les barques (chaloupe, barque) gardent leurs rameurs fixes.
- **Eau dans les coques** : chaque coque porte un masque invisible (profondeur seule) au niveau du plat-bord. L'ordre de rendu (`utils/renderOrder.ts`) doit rester : ciel → objets → masques → océan. Tout nouvel objet opaque garde `renderOrder` 0.
- **Deux calibres** : un navire peut avoir `ShipStats.deckCannon` en plus de `cannon` ; chaque `CannonMount` porte son `calibre` ('main' | 'deck') et le tir passe par `cannonStatsOf(ship, mount)` (portée, angle, dégâts, rechargement). Précision et portée s'appliquent aux deux.
- **Combat** : `combat/` (tir automatique, boulets ; coups critiques `combat/criticals.ts` : avaries par navire dans `Ship.crits` (`ship/shipCrits.ts`), effets `fx/critFx.ts`, textes `ui/critPopups.ts`, réglages `CRIT` ; une voile est repérée par `material.userData.sail`), `fx/` (particules low-poly sans transparence, une seule InstancedMesh par type ; les particules marquées `water` sont retirées si elles entrent dans une coque), `world/` (apparitions, collisions/éperonnage, butin, ciel). Éperonnage : dégâts selon la vitesse de rapprochement et la masse de l'autre (`Ship.mass`, recalculée par `applyLooks` avec `shipMass`), réglages `RAM`.
- **Dégâts visibles** : chaque `ShipModel` déclare `fireSpots` (foyers dans son repère, via `fireSpots()` de `parts/common.ts`) et `setDamage()` (voiles trouées par `parts/tornSail.ts` : un matériau cloné par voile, avec sa graine, via `tornSail.material(géométrie, axe du creux, emblème)` — 'z' voile carrée, 'x' foc ou aurique ; gonflement maximal selon la hauteur de la voile ; le même shader gonfle les voiles selon le vent, `TornSail.setWind` appelé par le `setWind` du modèle et `TornSail.setDeployment` par son `setSailAmount` (gonflement × déploiement), réglages `SAIL_BILLOW` ; une pièce posée sur une voile prend `tornSail.patchMaterial`). `Ship.damageLevel` pilote aussi la perte de vitesse ; `Ship.recoil()` donne le coup de roulis des tirs (`Buoyancy.kick` : oscillateur lent séparé, ajouté aux angles des vagues). Réglages : `DAMAGE`, `RECOIL`.
- **Ennemis** (`world/enemySpawner.ts`) : nombre max, rythme, flottilles et élites dépendent de `kills` (réglages `ENEMIES`). Une flottille partage un `EnemyGroup` (chef + alerte) ; les suiveurs ont une `FlotillaSlot` (`ai/enemyAI.ts`). Les apparitions ordinaires s'adaptent à ta flotte (`FleetPower` : taille de groupe ≤ nombre de navires, type ≤ ton plus gros + 1 cran ; `SHIP_SIZE_ORDER` / `sizeRank` dans `shipTypes.ts`). Une victime coulée par un allié hors de ta flotte est `uncounted`. Pirates alliés indépendants : `world/pirateTraffic.ts` + `ai/pirateAI.ts` (camp `ally`, de port en port, activités en route : chasse, pêche, patrouille ; `mooringSpot` tire une place au hasard et la réserve). Routes variées (sorties de crique, détours, cap qui ondule) : `ai/seaRoute.ts`, partagé avec le marchand escorté. Élite = livrée `ELITE_LIVERY` (paramètre de `createShip`, couronne peinte sur la plus grande voile : `Livery.sailEmblem` → `parts/sailEmblem.ts` via `tornSail.material(géométrie)`) + `strengthen` sur les stats. Boss : `BOSSES` de config (un `BossDef` par boss : type, livrée, temps qui le fait surgir, bonus, tactique ; La Veuve Noire par grosse tempête, Le Spectre dans le brouillard), `world/bossEncounter.ts` (`Bosses` : une rencontre par boss, une fois par épisode de son temps, lu par `Weather.levelOf`), `EnemySpawner.spawnBoss(id)`, `Enemy.boss` = son id. IA « acharnée » (`relentless`) qui ne fuit jamais, ou harcèlement (`harass`, réglages `HARASS` : attaque, retraite dans la brume, retour ailleurs ; `EnemyAI.hidden` le cache du radar, de la carte et de la barre). `leave()` quand son temps se lève ; il disparaît aussitôt si toute ta flotte a sombré (`fleetAlive`). Barre `ui/bossBar.ts`, un trophée par boss dans le registre. Livrées : `Livery.lantern` (couleur des fanaux), `Livery.tattered` (voiles en lambeaux même intactes).
- **Notifications** (`ui/notifications.ts`, via `hud.notifications`) : fil des navires coulés et popups de butin. Les dégâts passent par `Game.applyDamage(ship, dégâts, attaquant)` : l'attaquant (boulet, éperon) crédite le coup fatal au `FleetMember.kills`.
- **Campagne** (`campaign.ts`) : îles (`progression/islandState.ts` : fiche `ISLAND_INFO`, allégeance, rachat, marché, améliorations propres à chaque île, réserve : bois de la scierie et or des marchands alliés, récupérés par `Harbor.collectReserve` ; niveau de comptoir = `tradeLevel`), dernier port visité (réapparition), registre (`ledger.ts`), contrats des tavernes (`contracts.ts` : offres du jour par île pirate, tirées par `contractOffers.ts` — les mêmes genres partout, plus les convois du marché de l'île — et remplacées à chaque journée `CONTRACTS.dayLength` via `Contracts.tick` ; missions spéciales `SPECIAL_CONTRACTS` de config, uniques, `Contracts.specials`, réussite par `Contracts.complete` (`remove` = abandon ou échec), `Contract.special`, escadre ou embuscades imposées par `Contract.squadron` / `ambushes` ; `claimAt` = port où toucher la prime ou destination de l'escorte, difficulté de 1 à 5 étoiles tirée autour de `fleetLevel`, réglages par étoile dans `CONTRACTS`), butin rangé et navires coulés. Les actions du port de l'escale sont dans `progression/harbor.ts` (`harbor.island`) ; le panneau du port (E ou Tab près d'un quai) est `ui/port/` (un fichier par onglet, `PortContext`, pictogrammes dans `tabIcons.ts`). Genres de mission (étiquette et icône) : `missionType` / `MISSION_TYPES` de `contracts.ts`. **Marchands alliés** : `world/merchantTraffic.ts` (`Campaign.merchants`, réglages `ISLAND_TRADE` : ils arrivent du large vers chaque île à toi, `IslandState.deposit` à l'escale, repartent et disparaissent loin de toi ; en bleu comme les autres alliés ; les navires à protéger, en bleu ciel, viennent de `Campaign.escorts()`). **Routes commerciales** : `fleet/tradeRoutes.ts` (`Campaign.routes`, `FleetMember.trade` = `TradeOrder`, réglages `TRADE_ROUTES`), onglet `ui/port/routesTab.ts`. Un navire en commerce reste dans `Fleet.members` mais pas dans `Fleet.hand` : cales, pêche, formation, passage de barre, « toute la flotte a sombré » et taille de flotte face aux ennemis utilisent `hand`. Les navires marchands suivent leur route avec `MerchantAI` et mouillent via `mooringSpot` / `releaseMooring` (`ai/pirateAI.ts`). **Missions** (`missions/`) : `MissionDirector` démarre et suit chasse (`huntMission`), défense (`siegeMission` : le fort de l'île du contrat, `Fort.island`, assiégeants avec `EnemyAIOptions.siege` et `Ship.siegeTarget`, ouvrages touchés via les `structures` de `Projectiles`) et escorte (`escortMission` + `ai/merchantAI.ts`, navire de camp `ally` hors de la flotte, de `from` vers `claimAt`). Textes : `ISLAND_INFO.shortName` et `.fort` ; les escadres de mission viennent de `EnemySpawner.spawnSquadron(types…)` (persistantes ; types choisis par `squadronTypes` selon les étoiles). Le chantier et l'achat de navires ne sont accessibles qu'au port ; T reste partout (formation, barre, cales). Commandes contextuelles à l'écran : `ui/actionPrompts.ts` ; contrats suivis en haut à droite : `ui/questTracker.ts` (`hud.quests`). La réparation rapide au quai (`Campaign.repairAtPort`) s'arrête dès qu'un ennemi est à moins de `PORT.combatRadius` du port.
- **Cales et pêche** : marchandises (`progression/goods.ts` : poisson, rhum, épices) dans `FleetMember.cargo`, capacité par type + amélioration « Cale » (`holdCapacity`), fonctions de flotte dans `fleet/holds.ts` (le bois et l'or restent communs). Bancs : `world/fishSchools.ts` (logique) et `fx/fishSchoolFx.ts` (poissons, mouettes) ; pêche : `fleet/fishing.ts` (un allié pêcheur reçoit un `FleetMember.station`, que `AllyAI.holdStation` rejoint). Réglages `FISHING`.
- **Progression** : `progression/` (or, bois, places de flotte). Les niveaux d'amélioration appartiennent à chaque `FleetMember` (`fleet/fleet.ts`). Les stats sont toujours recalculées par `deriveStats(type, base, niveaux)` puis `applyModifiers` (`progression/modifiers.ts` : officiers et rang en `Ship.modifiers`, types de canons en `Ship.guns`), via `Ship.upgrade`. Les bases de `shipTypes.ts` ne sont jamais modifiées.
- **Équipage et personnalisation** : officiers (`fleet/officers.ts` : fonction, talent, trait, expérience ; `fleet/crew.ts` : `Campaign.crew`, candidats des tavernes renouvelés chaque journée, affectations, officiers uniques des missions spéciales), places par type `OFFICERS.slots`. Après tout changement d'un navire (amélioration, officiers, victoire, canons, pavillons), appeler `refit(member, crew)` (`fleet/refit.ts`). Effets hors caractéristiques lus via `factor(ship.modifiers, …)` : réparation, butin (`collectLoot`), cale (`capacityOf`), éperonnage, dégâts reçus, vent, radar (`Fleet.radarFactor`). Types de canons par calibre : `GUNS`, `FleetMember.guns` / `ownedGuns`. Rang selon `FleetMember.kills` (`RANKS`, `rankOf`). Ce qui se voit : `ship/shipDressing.ts` (`Ship.dressing`) : drapeau de rang sur `ShipModel.ensignStaff` (hampe de poupe, ou flèche du mât arrière quand une bôme passe au-dessus de la poupe), pavillons des boss coulés (`FleetMember.trophies`, sauf `hiddenTrophies`) sous le pavillon de `ShipModel.flagMount` (relevé par `setFlagLift` pour rester au-dessus des voiles), allure des fûts (échelle selon le type). Port : onglet Équipage (`ui/port/crewTab.ts`), type de canons au Chantier, rang et pavillons dans Navires.
- **Flotte** : `Fleet` gère le bateau piloté et les suiveurs (`ai/allyAI.ts` + formations ; pendant une escorte, `Fleet.guarded` = le navire à protéger, posé par `Game` depuis `Campaign.escorts()` : les suiveurs suivent `Fleet.anchor` et tiennent un poste en cercle autour de lui, `fleet/escortGuard.ts`), les naufrages et les réapparitions, et tient à jour la liste `ships` partagée. Les menus (port, T, M) héritent de `ui/parchmentMenu.ts` (barre de défilement « trait d'encre » : `.parchment::-webkit-scrollbar` dans style.css) (`toggle(code)` pour conditionner l'ouverture) ; un menu ouvert met le jeu en pause.
- **Sauvegarde** (`save/`, onglet Partie du menu Échap `ui/settings/saveTab.ts`) : `SaveData` versionné (`SAVE_VERSION`, `isSaveData`) gardé dans localStorage (`SaveStore` : liste illimitée, export/import .json). Chaque module garde son état via `snapshot()` / `restore()` (`IslandState`, `Ledger`, `Contracts`, `Crew`, `TradeRoutes`, réunis par `Campaign.snapshot/restore`) ; la flotte via `save/fleetSnapshot.ts` (`Fleet.adopt`). Charger ou recommencer recharge la page : `SaveManager.start` (flotte, avant la campagne) puis `finish` (le reste, puis `refit`) dans le constructeur de `Game`. Reprise à l'endroit exact ; pas de sauvegarde avec un ennemi à moins de `SAVE.enemyRange` ; les missions en cours recommencent ; ennemis, butin, pirates et marchands alliés ne sont pas gardés. **Tout nouvel état durable (ce qui doit survivre à un chargement) s'ajoute à un snapshot**, et un changement de forme augmente `SAVE_VERSION` avec une conversion des anciennes sauvegardes.
- **Réglages dans `src/config.ts`** : monde, vagues, caméra, combat, flotte, ennemis. Pas de nombres magiques dans la logique.
- **Vagues** : la formule de Gerstner existe deux fois, en GLSL (`ocean/oceanMesh.ts`) et en TS (`ocean/waves.ts`). Toute modification se fait aux deux endroits. La météo future modifiera `waves.list`. Les deux versions sont atténuées près de l'île par le même facteur de calme.
- **Météo** (`world/weather.ts`) : 6 temps (beau, brouillard, grand vent, pluie, orage, grosse tempête), chacun un `WeatherProfile` de `config.ts` (le beau temps vient de SKY/WORLD, sa houle varie seule). Un changement mélange l'état actuel vers le profil visé en `WEATHER.transitionTime`. Un nouveau temps = un profil + une entrée dans `PROFILES` et dans les boutons. Elle modifie la brume, le ciel (`skyUniforms` : `uSunlight`, `uFlash`), les lumières, la raideur des vagues de `waves.list` et la plage de force du vent (`wind.minKnots` / `maxKnots`), et publie `conditions` (portée de tir, détection) lue par les canons, le fort et l'IA ennemie. Gouttes dans `fx/rain.ts` et filets de vent dans `fx/windStreaks.ts` (tout dans le shader), éclairs dans `fx/lightning.ts` (dégâts et secousse via des rappels vers `Game`). La liste des vagues = houle (`OCEAN.waves`, × waveFactor) puis clapot (`OCEAN.chopWaves`, × chop, nul par temps normal ; les vagues sans raideur sont sautées côté CPU). Écume de tempête et direction du vent passent au shader par `ocean/seaState.ts`. Paquets de mer : `world/heavySeas.ts`. La météo réécrit la raideur des vagues dès que la houle change : les réglages de vagues du panneau ?debug ne tiennent pas.
- **Flottaison** (`ship/buoyancy.ts`) : ressorts qui suivent la vitesse de la vague (pas d'amortissement absolu, sinon retard) et se durcissent près de `BUOYANCY.maxOffset`. Ne pas remettre de borne « dure » sans transition (à-coups). Inertie des gros navires en tangage et roulis selon la masse (`BUOYANCY.heavyMass`, `inertiaExponent`, coude `inertiaKneeMass` au-delà de la corvette…), pilonnement réduit (`heaveExponent` : part de la hauteur de l'eau suivie ; ralentir le ressort de hauteur ne réduit pas la vitesse verticale, qui vient de la grande houle, et décolle la coque), avec pour eux un durcissement réduit et une vitesse d'angle plafonnée en douceur (`maxTiltRate`, tanh) : pas de bascule brutale au passage d'une crête. À régler en mesurant tangage et roulis par grosse tempête (face à la houle, en route), pas à l'œil. Lieux de la carte : `world/landmarks.ts` (positions partagées avec le décor).
- **Traces dans l'eau** (`ocean/wakeMap.ts`, `ocean/wakeShaders.ts`) : texture vue de dessus (R = écume, G = eau lissée, B = eau qui frémit au-dessus d'un banc), centrée sur le joueur et alignée sur les texels, recopiée/étalée/pâlie puis « tamponnée » chaque image (fusion MAX), lue par l'océan (`wakeTrace`). Le liseré d'écume le long des coques (`hullFoam`, en route, en virage et à l'arrêt) est calculé dans le shader à partir de `uWakeShips` / `uWakeHulls` et du profil de flottaison de chaque coque (`ShipModel.waterline`, tiré de `HullShape.waterlineProfile` ; `WATERLINE_SAMPLES` = 8 doit rester égal au `float[8]` du shader). Le liseré n'est dessiné que pour les navires proches de la caméra et devant elle (`WakeMap.updateBowWaves`, `GRAPHICS.hullFoamRange`) : chaque pixel d'eau parcourt cette liste. Il suit l'assiette de chaque coque (`uWakeAttitudes` : hauteur, `Ship.pitch` / `roll`, tirant d'eau `WAKE.hullDraft`) : il s'efface là où la coque est soulevée hors de l'eau. Purement visuel : la flottaison ne les voit pas (ne pas en faire un déplacement de vagues). Un nouvel effet qui marque l'eau = un type de tampon dans `STAMP_FRAGMENT`.
- **Îles** (`world/island.ts`) : chaque île (`Island`, forme dans `ISLANDS` de config : la Tortue, Port-Sabre) a une formule polaire (rayon + lobes − crique) qui donne sa côte, sa distance signée `sdf` (positive en mer), son relief (collines ou falaises) et le calme des vagues. `land` interroge l'archipel (île la plus proche) : navigation, collisions, boulets, vagues, flotte passent par lui ; `tortuga` / `sabre` / `ISLAND_LIST` pour ce qui est propre à une île. Le GLSL (`ISLAND_GLSL`, tableaux d'uniforms, `ISLAND_LOBES` = 4 ondulations par île) refait les mêmes calculs pour toutes les îles : modifier les deux. Le décor de toutes les îles est posé par `world/worldBuilder.ts`. Décor dans `islandTerrain.ts` et `port.ts` (paramétrés par île), `fortModel.ts` (fort bastionné, plans `FORT_LAYOUTS` : fort de la Tortue, citadelle de Port-Sabre ; `fort.ts` = ses canons, un secteur de tir chacun, et sa vie pendant un siège), `lighthouse.ts` (phare qui grandit avec son amélioration, faisceaux additifs sans brume par temps sombre, lus sur `skyUniforms.uSunlight`) ; la végétation évite le fort et le phare ; contact avec la côte dans `landCollision.ts`. Les IA évitent la terre via `avoidLand` dans `steerTo` (`ai/steering.ts`) : tout nouveau pilotage d'IA doit passer par `steerTo`.
- **Repère d'un bateau** : proue vers +Z local, bâbord (gauche) vers +X, tribord vers -X, Y vers le haut, ligne de flottaison à y = 0. Cap 0 = +Z, et le cap augmente en tournant vers bâbord.
- **Clavier** : utiliser `KeyboardEvent.code` (ZQSD en AZERTY = WASD en QWERTY). Pour une touche « lettre » (mnémonique) qui n'est pas au même endroit selon le clavier, donner les deux codes (ex. M = `KeyM` en QWERTY, `Semicolon` en AZERTY) ; les menus parchemin acceptent une liste de touches.
- **Performances** : viser les PC portables modestes. Pas d'ombres, pas d'allocation par image dans les boucles chaudes. Le coût est surtout le GPU (shader de l'eau, résolution, anticrénelage). L'eau noyée dans la brume sort tout de suite de son shader ; `world/fogCulling.ts` ne dessine pas le décor des îles ni les navires au-delà de la brume (profondeur dans l'axe de la caméra, comme la brume). Tout nouvel effet coûteux suit une densité existante ou a son réglage.
- **Affichage et réglages** : `render/display.ts` (moteur de rendu dans un conteneur `.viewport` fixe, où la caméra écoute la souris ; la toile ne change de taille qu'au début d'une image, avant le dessin (redimensionner l'efface : sinon, éclair) ; les mesures prises pendant une absence (Alt+Tab) sont oubliées ; résolution = choix × échelle de `render/dynamicResolution.ts`, plafonnée à la densité de l'écran ; l'anticrénelage recrée le moteur ; limite d'images ; compteur ; précompilation des shaders), `settings/settings.ts` (réglages du joueur, préréglages `GRAPHICS.presets`, gardés dans localStorage), `render/quality.ts` (`applyQuality` : affichage, grille et détails de l'eau, sillages, pluie et vent, `particleBudget`). Menu Échap `ui/settings/` (onglets Jeu et Graphismes) ; Échap est géré une seule fois par `ParchmentMenu` : il ferme le menu ouvert, sinon ouvre le menu déclaré par `openOnEscape()`. Les menus parchemin sont créés par `ui/menus.ts`.
